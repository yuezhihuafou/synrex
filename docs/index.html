Synrex connects ordinary ChatGPT conversations to real engineering work on your own machines—with durable tasks, inspectable evidence, workflow recovery and optional execution peers.

Explore early-access release ↗View source on GitHub

One owner per installation. No hosted account, managed cloud or separate reasoning agent required.

Built for real engineering loops

More than one-off tool calls.

The model decides what to do. Synrex executes within permitted workspaces and returns concrete artifacts and state that can be inspected and recovered.

Durable tasks

Run long commands without tying process lifetime to a single MCP response. Retrieve bounded status and full logs later.

Workflow recovery

Persistent task and workflow identities preserve checkpoints, evidence and context for resumed engineering work.

Multi-host execution

Keep your main Linux owner machine in control and connect optional compatible peers for additional workloads.

Inspect before accepting

Workspace-aware code access, Git worktrees, changes, test results and retrievable execution receipts.

Operational Console

An owner-authenticated browser surface for service, workflow and diagnostic visibility, separate from ChatGPT.

Architecture boundaries

Versioned project intent and deterministic checks help maintain consistency across repeated AI edits.

Synrex does not run a hidden model loop and cannot wake a finished ChatGPT turn automatically. Its job is to expose reliable execution capabilities, not replace the conversational model.

Quick start

Start with a disposable repository.

Linux is the primary tested environment. You need Node.js 22.19+, pnpm 11.25.0, Git and a Bash-compatible shell. Configure your own authenticated MCP endpoint before remote access.

Read the trial guide ↗
git clone https://github.com/yuezhihuafou/synrex.git
cd synrex
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
pnpm build
npm link
synrex init
synrex doctor
Transparent about its maturity

Public preview, not a performance claim.

Synrex is actively used in a self-hosted Linux engineering environment, but broad third-party deployment, fault-injection coverage and controlled end-to-end comparisons are still in progress. Windows remains best effort. Try it, report reproducible issues and help sharpen the evidence.
