## Deliberately open acceptance gates

1. **Real client tool refresh:** the connected ChatGPT host may still display
   its cached six-tool schema. The live schema probe in locked OAuth enrollment
   mode verified compiled 17-tool identity but returned
   `liveAuthenticatedToolListVerified=false`. Do not equate this with a fresh
   authenticated 17-tool `tools/list` in a new ChatGPT conversation.
2. **Performance:** no controlled GPT+original-Dev versus GPT+Synrex benchmark
   yet measures task completion, model-context bytes, latency, poll calls or
   human takeovers. The 10-second bounded task_wait is implemented and covered
   by QA, not yet quantitatively validated in live model turns.
3. **Fault injection:** generic durability, restart recovery and duplicate
   workflow create passed; ambiguity under link loss at a non-idempotent
   remote write and cancellation still need controlled failure-injection runs.
4. **Rollback drill:** the systemd activation script contains a fail-and-revert
   path and the previous drop-in and release remain available, but **no live
   post-cutover reversal drill was performed**. Do not claim that it was.
5. **Peer compatibility:** gateway and optional Windows did not participate
   in this local source/owner release acceptance. Test peer contracts
   separately; do not require peer Git SHA equality.

The publicly visible OAuth issuer, MCP URL, existing secrets, state DB format
and Console cookie identity were not changed to rename the product. The
`healthz` compatibility field may continue to identify the legacy
`devspace` service internally.
