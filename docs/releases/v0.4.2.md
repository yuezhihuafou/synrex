# Synrex v0.4.2 — Windows portable install repair

These notes describe the intended v0.4.2 patch release. The immutable tag,
published archive, checksums and CI evidence—not this document—establish whether
the release has been published.

## Why this patch exists

Real Windows x64 testing of v0.4.1 found that pnpm could install successfully
in a temporary directory but create absolute Junction targets. Moving that
directory to `releases/v0.4.1` broke module resolution, including
`@clack/prompts`, although `--stage` had reported success. A separate initial
`npx` failure also lacked sufficient diagnostics when its output was on stdout.

## Changes

- Verify release archive content and digest in a temporary staging directory;
  move the unpacked package into its final version directory **before** pnpm
  creates dependency links, still using pnpm 11.25.0 and the exact published lock.
- Verify actual CLI execution from the final path before accepting staging,
  activation or rollback. Never treat package metadata alone as success.
- On failed installation, remove only the incomplete new release; preserve
  existing versions and the active portable version pointer.
- Report the child-process exit code and bounded stdout/stderr on installation
  failures, and prevent regressions with native and synthetic Junction tests.

## Compatibility and scope

- Node.js >=22.19 and <27. Existing CLI aliases, MCP/OAuth endpoints, Owner
  credentials, SQLite, worker identity and interface contracts are unchanged.
- Linux production remains a separate pinned release and is not switched by
  publishing this patch. A Windows peer already using v0.4.1 is not implicitly
  upgraded by the GitHub Release.
- The manual Windows reproduction used the official v0.4.1 archive with the
  repaired installer in a fresh isolated prefix. Formal v0.4.2 release gates
  still require passing CI, signed tag provenance, checksums and assets.

## Installation and rollback

1. Back up the existing configuration and state before changing live services.
2. Download the published `synrex-0.4.2.tgz` and `SHA256SUMS` from this tag
   after publication. Verify the archive digest.
3. Run `node deploy/portable-install.mjs --stage --version 0.4.2` with an
   isolated `--prefix`. A successful stage now verifies the **final** CLI path.
4. Run `--activate --version 0.4.2` only after testing. Activation changes
   the portable launcher pointer but never restarts a live service.
5. Run `--rollback` to switch back to the previous verified portable version
   if required. Owner production deployment follows its separate audited path.

Do not move or overwrite v0.4.1's immutable tag or GitHub assets.
