# Synrex v0.4.5 — explicit node administration sessions

This release adds `open_host(node)` for host administration without requiring
the model to guess an unrelated project checkout path. Selecting a host creates
a normal session anchored to the node's advertised root, so authenticated
`exec_command` routing and durable-task ownership remain unchanged.

## Changes

- Require an explicit, online node alias or ID for host management sessions.
- Reuse existing `open_workspace` and `exec_command` contracts on remote peers;
  project-root checks and node placement protections remain intact.
- Add routing coverage for the new entrypoint and synchronize the MCP tool
  manifest and compact tool-schema budget.
- Stabilize durable-task regression timing by awaiting runner completion.

## Upgrade and rollback

- Owner promotion uses the audited `deploy/promote-main.sh` transaction with
  backups, full regression and authenticated smoke checks.
- Linux/Windows peers should stage the verified archive before changing an
  active runtime; preserve existing OAuth identity, node configuration and
  running task state. Never replace a dirty development checkout.
- Portable installs may roll back to the previously staged version.

Availability requires a successful exact-commit main CI run, an annotated tag,
and a published GitHub archive plus checksums; these notes are not proof of
deployment on any host.
